SaveSync

Steam Cloud for any game. Your saves, your repo, every machine. Built for the FitGirl-on-PC, Steam-on-Ally life.

StackTauri 2 · Rust · React 19
TargetsWindows · Linux
BackendGit + LFS

01 Problem

Steam Cloud is invisible magic when it works. The minute a game lives outside Steam — repacked, GoG-with-no-Galaxy, Epic, itch, standalone launcher — saves become local-only files. Cross-machine play means USB-sticks, manual folder copies, and inevitably overwriting the wrong version.

Pain

USB-shuttling saves

Copy from %APPDATA%/EldenRing to a stick, plug into ROG Ally, hope nothing got overwritten in the wrong direction.

Pain

No version history

Save got corrupted? Bad romance choice in BG3 you want to undo? Local files = no time machine.

Pain

Silent overwrites

Two machines, one folder. Whoever copied last wins.

02 Locked decisions

Every row below is a decision made during grilling. These are the rails — if a downstream choice contradicts one, that's a re-open, not an implementation detail.

Form factor
Portable single-binary GUIDrop on a USB stick. No installer. Tray icon + window.
Platforms
Windows + LinuxWin 10/11 first, AppImage for Linux/SteamOS/Bazzite. Mac deferred.
Stack
Tauri 2 · Rust + React~10MB binary. Frontend uses Tailwind + Motion for the design language.
Backend
Real git via git2 + auto-LFSFiles >50MB get LFS-tracked automatically. Any git host works; GitHub is the happy path.
Repo shape
One private repo per user, folder per gamesavesync-data/elden-ring/, savesync-data/bg3/, plus root savesync.json manifest.
Auth
GitHub OAuth Device Flow + PAT fallbackBrowser flow for GitHub; manual token paste for self-hosted Forgejo / GitLab / Gitea.
Save discovery
Bundled Ludusavi manifest + manual override~13k known games, MIT-licensed. Plus Steam library scan during onboarding.
Trigger
Auto on game launch + exitProcess watcher polls every 2-3s. Pull-on-launch, push-on-exit. Optional wrapper-launcher button for paranoid mode.
Conflicts
Silent newest-wins, loser to backup branchOlder version preserved at backup/<game>/<machine>-<timestamp>. Nothing is ever lost.
Add-game safety
Detect existing local save before first syncWhen adding a game on a new machine, if both local AND remote exist, user chooses: local / remote / keep both.
Machine ID
Hostname-by-default, user-renameableEvery commit tagged with machine name. Shows up in conflict UI, history, backup branch names.
Onboarding
3-step wizardConnect GitHub → Pick/create repo → Steam scan + add found games.
Updates
Tauri built-in updater · GitHub Releases · SignPath signedNo SmartScreen warnings on Windows. Linux AppImage updates via appimageupdate.
Encryption
None in v1Private repo IS the boundary. Avoid forgot-passphrase tickets. Opt-in encryption considered for v2.

03 Repo structure

One private repo per user. Each tracked game lives in a top-level folder. A root manifest tracks game metadata and machine roster. Backup branches catch every conflict loser.

savesync-data/ ├── savesync.json # manifest: games, machines, schema version ├── README.md # auto-generated, "managed by SaveSync" ├── elden-ring/ │ ├── ER0000.sl2 # the actual save (~50KB binary) │ ├── ER0000.sl2.bak │ └── .savesync-meta.json # last machine, mtime, hash ├── bg3/ │ ├── PlayerProfiles/... │ └── .savesync-meta.json └── rdr2/ # larger saves auto-routed to LFS ├── SGRDR15555_00.sav # 240MB → tracked via LFS └── .savesync-meta.json Branches: ├── main # current live state across all games ├── backup/elden-ring/Desktop-PC-2026-05-11-1432 ├── backup/bg3/ROG-Ally-2026-05-10-2215 └── backup/rdr2/Desktop-PC-2026-05-09-1801

04 Scope — v1 vs deferred

Ship lean. Every item on the left is required for the v1 promise of "seamless save sync between two machines." Items on the right are interesting but parked.

In v1

  • Tauri scaffolding for Win + Linux, single-binary builds
  • GitHub OAuth Device Flow + PAT fallback
  • Token storage in OS keychain
  • git2-based clone / fetch / commit / push
  • Auto-LFS routing for files >50MB
  • Ludusavi manifest bundled + Steam scan
  • Manual game-add with folder picker
  • Process watcher + push/pull on launch/exit
  • Newest-wins conflict resolution with backup branches
  • Machine naming (hostname default, renameable)
  • Detect existing local saves on add-game
  • 3-step onboarding wizard
  • Game list UI with Sync / Pause / Open Folder per game
  • Activity log (last 50 sync events)
  • Tauri auto-updater + SignPath signing
  • Tray icon with quick status

Deferred to v2

  • Client-side AES encryption (opt-in)
  • Share-a-save with a friend (gift links)
  • Mod / load-order syncing
  • Steam Cloud → SaveSync migration helper
  • winget / scoop / Flatpak packaging
  • macOS support

05 Roadmap — phases

Foundation → core sync → onboarding → polish. Each phase produces something demoable. Phase boundaries map cleanly onto Plane epics SAVE-1 through SAVE-6.

0Foundation

Tauri skeleton + tooling

  • Tauri 2 + React 19 + Vite + Tailwind 4 + Motion
  • CI: GitHub Actions matrix building both targets
  • Design tokens + base components (button, card, modal, toast)
  • OS keychain access via keyring-rs
1Sync core

Headless save → git → save loop

  • git2 wrapper: clone, fetch, commit, push, pull, branch
  • LFS routing for files >50MB
  • Manifest schema (savesync.json + .savesync-meta.json)
  • Hash-based change detection on save folder
  • Conflict resolution: newest-wins + backup branch creation
  • Headless CLI for testing the loop end-to-end before any UI
2Detection

Process watcher + game database

  • Bundle Ludusavi manifest at build time
  • sysinfo poll loop with debouncing
  • Save path resolution per OS
  • Wrapper-launcher mode + file-watcher safety net
3Onboarding

Auth + first run wizard

  • GitHub OAuth Device Flow + PAT fallback
  • 3-step wizard UI with skippable steps
  • Steam libraryfolders.vdf parser + game match
  • Existing-save detection on add-game
  • Repo bootstrap (create if missing via GitHub API)
4Surface

UI + tray + activity

  • Main window: game list, status per game, last sync time
  • Per-game detail: history, force push/pull, open folder, rename
  • Tray icon with status states + quick actions
  • Activity log + settings page
5Ship

Updater, signing, release

  • Tauri auto-updater wired to GitHub Releases
  • SignPath OSS signing pipeline for Windows binary
  • Linux AppImage with appimageupdate metadata
  • First public release: landing page hosted on your server
